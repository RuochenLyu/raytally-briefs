## 灵感

HTML 混音接力
远程混音时，用一个可运行的 HTML 文件传递乐器、分轨和版本血缘，打开即可继续创作。

## 产品概念

异地合作的音乐人常把一段节拍发成音频，却很难把工程、音色和改动缘由一起交给下一位。这个产品把一首电子音乐小样封装成单个 HTML 文件：浏览器打开后就能离线播放，合成器参数、节拍格和当前分轨都留在文件里。 创作者拖入一段人声、鼓点或旋律后，可直接调整速度、循环长度和效果参数，再导出新版本。收件人无需安装同款软件或插件，双击文件便能试听、改写并续作。界面把每个声部保留为可开关的小轨道，让接手者知道哪里还能补录，哪里已被锁定。 每次导出都会写入父版本指纹、修改者备注和渲染参数。打开新文件的人能回看它从哪一版接力而来，也能在需要时切回任意旧版本重新分叉。比赛投稿或教学作业还可附上一段验证信息，说明最终音频由哪一组规则和参数渲染。 首版提供四轨循环、基础合成器、音频导入导出和离线版本链。它不试图成为完整录音棚软件，先让一段灵感能作为可运行的作品文件，在朋友之间不断被打开、改写和传回。

## 方向判断（以下为模型推断，未经独立验证）

目标用户：核心用户是分散在不同时区的电子音乐人。他们刚收到一段节拍，想在灵感未散时立刻续作。此时最怕先安装软件、寻找插件或追问工程版本。音乐教师与比赛组织者也适用。他们需要收作业或投稿时，一并保留可试听内容、参数和修改来源。

最小切入点：音频层用 Web Audio API 搭四轨节点图。浏览器已具备音源、滤波、压缩和精确调度能力。 拖入素材后，用 File API 读取音频字节。工程状态保存为规范化 JSON，并嵌入导出的 HTML。素材可编码进文件，首版应限制时长与总体积。导出时对状态、素材和父指纹计算 SHA-256。离线渲染可交给 OfflineAudioContext。验证页先核对输入、参数和版本链，不承诺跨浏览器音频字节完全一致。功能取舍应守住四轨、循环和基础效果。暂不做实时协作、插件兼容和无限撤销。

最强反方：把音频素材塞进 HTML 会迅速增大文件。邮件、聊天软件和浏览器可能因此拒收或变慢。不同浏览器的解码与音频实现还可能产生渲染差异。若宣传成可验证音频，字节不一致会直接损害信任。更稳妥的是先验证素材、参数和处理链。外部人声与采样还涉及授权和隐私。文件一旦转发，原作者很难撤回其中素材。版本树也会随多次分叉变得难以理解。若用户最终仍需回到专业 DAW 混音，重复整理分轨会削弱便利。

以上是模型基于灵感本身与已核验事实的推断，请当作方向假设与真实约束对待：不要默认「最强反方」已被解决，也不要据此在产品里写下确定性结论。

## 竞品与缝隙（模型推断）

- Soundtrap：Soundtrap 已提供浏览器录音、虚拟乐器和混音工具。它支持实时协作、聊天、视频和时间线评论。项目修改会自动保存到云端。 付费方案还能查看旧版本，并把旧版另存为独立项目。 这套体验适合同一团队持续在线制作。官方文档强调云端项目、邀请协作者和音频下载。尚未看到可离线传递的自包含工程文件。接收者仍需进入平台及其项目权限体系。HTML 混音接力的缝隙是异步文件交接。作品状态、素材和父版本可随附件一起移动。它不取代完整工作室，而是减少账号、插件和工程格式的协调。
- Soundation：Soundation 是浏览器内的云端协作工作室。它支持上传音频与 MIDI，并提供合成器和效果器。协作者可在同一项目实时看到彼此操作。项目还能通过邀请或公开链接交给他人。 这些能力覆盖了在线共创和完整歌曲制作。它的核心对象仍是平台托管的共享项目。官方页面未展示可下载的自包含编辑工程。链接失效、权限变化或离线场景会中断接力。HTML 混音接力把作品本身变成协作载体。收件人拿到文件即可查看分轨与修改来源。其优势不在功能数量，而在长期保存和跨工具传递。代价是轨道、素材容量和效果器必须严格受限。
