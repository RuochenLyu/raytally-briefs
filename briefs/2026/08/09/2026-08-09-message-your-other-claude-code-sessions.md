## 灵感

多会话编码值班台
并行运行多个 Claude Code 会话时，集中分工、传递结果，并在代理改到同一处前拦住冲突。

## 产品概念

开发者同时开着多个 Claude Code 会话修同一仓库时，先给每个会话分配角色和工作树，例如改接口、补回归测试、排查线上错误。值班台读取各会话声明的目标、当前分支和正在触碰的文件，把原本散在终端里的并行工作摆到一张可查看的任务板上。 某个会话完成接口调整后，相关测试会话会自动收到变更摘要、提交号和需要验证的行为。会话发现自己依赖另一项尚未完成的改动时，可以发出带文件和函数范围的请求，不必由开发者复制整段聊天记录。开发者只需在值班台确认优先级，其他消息按依赖关系送达对应会话。 两名代理准备编辑同一文件区段时，后启动的一方会被暂时锁住。页面明确显示谁持有修改权、预计何时释放，以及另一方能否先改测试或另一个模块。每次任务完成后，测试结果、改动说明和未解决假设会沉淀到可合并成果区，开发者能逐项审阅，而不是从多扇终端里猜哪份代码可信。 首个版本支持 Claude Code、Git worktree 和文件级冲突预警，先解决一人并行指挥多个会话的混乱。它不替团队自动合并冲突，也不代替代码审查；最后的合并按钮仍由开发者掌握。

## 方向判断（以下为模型推断，未经独立验证）

目标用户：面向独自维护中大型仓库的开发者，也包括小团队技术负责人。赶修线上故障、跨层改接口或补回归时，他们会同时启动多个会话。此时真正稀缺的是对依赖与改动归属的掌握。终端一多，人工转述和逐个查状态就会拖慢合并判断。

最小切入点：本地守护进程先调用 `claude agents --json`，获取会话目录、名称和状态。 `SessionStart` 钩子登记角色、分支、工作树和任务目标。`PreToolUse` 钩子读取编辑工具的文件路径，命中占用时用退出码 2 暂停写入。 完成后读取 Git 提交与测试输出，生成待审阅成果。会话间摘要通过 `SendMessage` 或会话套接字发送。 首版只做文件级租约，不做自动合并和语义冲突判断。

最强反方：Claude Code 已有 Agent view、工作树和跨会话消息，基础看板很容易被原生功能覆盖。 文件级锁还会把本可独立完成的改动错误串行化。若放宽到函数级，语法解析、重命名和生成文件又会带来漏报。钩子阻止写入时必须给会话足够上下文，否则代理可能反复重试。跨会话消息还受系统、供应商与权限设置限制。 一旦误拦频繁发生，开发者会绕过值班台，协调状态随即失真。

## 竞品与缝隙（模型推断）

- Claude Code Agent view、跨会话消息与工作树：Claude Code 原生组合已经覆盖大部分表层需求。Agent view 能集中展示后台会话，标出工作、阻塞和完成状态。它还能派发任务、回复会话、查看结果，并关联工作树与拉取请求。 跨会话消息又让独立会话传递纯文本摘要。 不过，普通终端会话要转入后台才完整进入 Agent view。公开文档也未说明跨会话文件占用、函数范围协商或依赖看板。交接仍以消息和会话摘要为主，缺少统一的待合并成果结构。该值班台的缝隙，是把原生能力编排成可审阅的工程流程。
- tmux、Git worktree 与交接文件：一种惯用做法是用 tmux 分屏，每个会话放进独立 Git worktree。HN 讨论中，一名开发者还加入记忆树、交接文件和协调器，用来减少重复上下文。 这种方式透明、可脚本化，也不依赖额外桌面应用。工作树能隔离即时写入，却只是把部分冲突推迟到合并阶段。角色、依赖和完成条件仍需开发者自行维护。交接文件容易过期，也无法确认接收方是否已经处理。脚本通常只能比较文件或提交，难以表达谁暂时拥有某段代码。值班台可把这些约定变成状态、提醒和可追踪的协商记录。
