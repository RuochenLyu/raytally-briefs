## 灵感

随剧情变奏的跑团原声
跑团主持人点选剧情事件，现场配乐就在同一主题里无缝变奏，结束后还能回放整局原声。

## 产品概念

跑团主持人准备开场时，先为角色、地点和危险等级设定几条短旋律主题，例如港口的低音、反派的弦乐和追逐时的鼓点。产品据此生成一套能连续变化的场景音乐，而不是一串彼此割裂的循环曲。主持人还能先试听平静、紧张和失控三个版本，决定哪种音色适合这次冒险。 游戏进行中，主持人只需点选“发现线索”“追逐”“谈判破裂”等事件，或拖动紧张度滑杆。系统从当前小节开始改变配器、节奏和力度，让同一主题自然变奏。角色在同一场景里行动时，音乐不会突然切歌，玩家能听出危险正在逼近，却不会被生硬转场拉出故事。 主持人可以为关键剧情节点留下标记。整局结束后，产品把实际发生过的场景、主题变化和高潮位置排成一段原声回放，玩家可重听这晚的冒险。下一次继续同一战役时，还能带回角色原有的音乐线索，让新场景听起来仍属于同一个世界。 初版提供少量预设乐器和剧情事件，重点处理现场无缝变奏，不替主持人自动写剧情或判断玩家行为。它把配乐从开场前要反复挑歌的负担，变成桌上一个能跟着故事呼吸的控制台。

## 为什么是现在（有事实支撑）

截至 8 月 1 日观察，Mubert API 位于 Product Hunt 新品流第 10 位，页面正强调轨道、分轨编辑与音乐一致性。 官方接口已有流式播放、无缝强度变化和分轨替换，主持人因而更容易把挑选循环曲的问题改造成现场控制音乐状态。

## 方向判断（以下为模型推断，未经独立验证）

目标用户：核心用户是重视氛围、又不想整晚兼任音乐 DJ 的跑团主持人。开团前，他需要快速确定整场冒险的声音身份。游戏中，注意力必须留给叙事、规则和玩家反应。此时只点剧情事件或拖动紧张度，才不会打断讲述。连续战役的主持人更需要角色主题延续和整局回放。

最小切入点：用 Mubert API 创建同一提示词、调性和速度下的音乐素材。官方接口支持流式音乐，以及低、中、高强度的无缝变化。它也能替换或删除乐器与分轨。 开局前生成平静、紧张和失控三个版本，并缓存可播放地址。浏览器端用 Web Audio API 对齐小节，安排淡入淡出。事件按钮只映射强度、鼓组、低音和效果层。关键节点记录事件、时间和所选状态。首版不承诺任意旋律实时重写，先验证连贯过渡与回放。

最强反方：Mubert 当前文档确认的是强度切换和轨道编辑，并未保证按当前小节实时改写同一旋律。相似生成也可能改变主题身份。若三个版本的速度、段落或拍点不齐，过渡仍会显得突兀。预生成和缓存会增加开局等待，也会消耗生成额度。长局中的网络抖动可能造成断流，必须准备本地降级音轨。原声回放还涉及许可范围与导出权限。若实测无法让玩家持续认出主题，这个卖点就应收缩为自适应分层播放器。

## 以小博大（模型推断）

第一批用户可从 Foundry、Roll20 和跑团主持人社区获取。用短视频展示同一港口主题从谈判转入追逐，比介绍生成模型更直观。提供一套可直接开局的免费冒险配乐模板，让主持人带进真实团测试。回放原声可生成带事件标记的分享页，自然触达同桌玩家和其他主持人。

## 竞品与缝隙（模型推断）

- Syrinscape：Syrinscape 已把跑团音乐、环境声和触发音效做成庞大素材库。主持人能混搭场景，也能上传自己的音频。玩家可远程收听，无需单独付费或安装。 它更像内容丰富的现场音效台。主持人仍要选择场景、音乐和触发音。不同音乐之间主要依赖切换与混搭。这里的缝隙是把角色主题保留在整场音乐中。剧情升温时，不必寻找另一首战斗曲。主持人只表达事件和紧张度，配器变化由系统完成。战后回放还能按实际事件恢复音乐走向。
- Crossblade：Crossblade 允许 Foundry 主持人准备同步音频层。触发游戏事件后，各层会淡入或淡出。它已经实现了垂直重配器式的自适应音乐。 为获得较好效果，各层通常要同速并从同一点开始。主持人还得预先找到或制作成套音频。它解决播放控制，却不负责生成主题与变体。当前产品可把这段准备工作压缩成几条主题设定。事件按钮仍由主持人掌控，避免自动判断剧情。真正需要验证的是生成结果能否稳定保持旋律身份。

## 怎么赚钱（模型推断）

向主持人收取月度订阅费，包含一定的直播配乐时长、战役存档和原声导出额度。超出部分按配乐时长计费，避免生成与流媒体成本失控。
