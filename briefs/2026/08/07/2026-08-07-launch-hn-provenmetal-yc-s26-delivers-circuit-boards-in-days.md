## 灵感

板子到货前的固件

## 产品概念

电路板已经送厂、实物还在运输时，固件团队往往只能等板子到手再开始验证。工程师把 KiCad 或 Altium 导出的板图、网络表、BOM 和主要器件资料放进项目后，产品先读出芯片引脚、总线连接和外设关系，生成一套能被固件调用的虚拟硬件层。 开发者可以在 CI 中编译真实固件，让模拟器对 GPIO、I2C、SPI、传感器中断和常见外设响应作出预设反馈。页面会把每个模拟行为连回原理图和器件资料，标明哪些来自设计文件，哪些仍需工程师补充。首轮上电检查会针对电源、通信和关键引脚生成可跑的测试序列。 板子到货后，同一批测试切换到调试器和仪器即可运行。产品把模拟期通过、真板失败的项目单独列出，帮助团队定位是原理图假设错误、焊接问题还是固件时序问题。这样硬件运输省下的几天不会重新耗在临时搭测试环境上。 第一版优先覆盖常见微控制器和标准接口，不承诺准确模拟复杂模拟电路、射频效应或每一种专有芯片。它的目标是让固件尽早进入可测试状态，并让真板到手后的第一次上电有一套现成的验收路径。

## 方向判断（以下为模型推断，未经独立验证）

目标用户：适合已有原理图、刚把首版或改版 PCB 送厂的嵌入式团队。此时硬件连接基本冻结，固件接口却尚未经过整板验证。固件负责人需要尽早发现引脚、总线和启动顺序问题。硬件负责人则希望板子到货后，测试能立即迁移到实物，而不是重新解释整张原理图。

最小切入点：先接收 KiCad 工程，以及 Altium 导出的网络表和 BOM。KiCad CLI 已能导出多种网络表和 XML BOM，可作为稳定入口。 解析后建立器件、引脚、网络和总线关系图，再让工程师确认主控、供电域与关键外设。执行层不自研完整模拟器，而是生成 Renode 平台描述和少量外设桩。首版只覆盖 GPIO、UART、I2C、SPI 和定时中断。测试采用统一场景格式，仿真端调用模型，真板端改接调试器与串口代理。复杂模拟电路、射频和未建模专有器件仅标记为待实测。

最强反方：设计文件只能说明连接关系，无法自动给出器件在各种输入下的真实行为。数据手册表述不完整时，生成的模型容易掩盖时序、复位和电气假设错误。每增加一种主控或专有外设，都要维护模型、示例和回归测试。仿真通过若被团队误当成硬件保证，首次上电反而可能更冒进。真板执行还会受到调试器、仪器和夹具差异影响，使同一测试难以真正无缝迁移。若早期项目需要大量手工建模，节省的等待时间会被配置成本抵消。

以上是模型基于灵感本身与已核验事实的推断，请当作方向假设与真实约束对待：不要默认「最强反方」已被解决，也不要据此在产品里写下确定性结论。

## 以小博大（模型推断）

首批用户可从嵌入式 CI、KiCad 自动化和 Renode 的 GitHub 项目中获取。发布一个可直接运行的示例仓库，展示从网络表到 CI 测试，再到真板复跑的完整提交历史。针对常见开发板制作公开模板，让工程师先用现成设计验证流程。Hacker News 这批快速制板讨论者，也适合用具体板卡案例定向触达。

## 竞品与缝隙（模型推断）

- Renode：Renode 已能运行未经修改的嵌入式软件，并模拟处理器、外设和传感器。它可接入 Robot Framework，在 CI 中执行测试，还允许用 Python 或 C# 补充外设模型。 对有仿真经验的团队，它已经是一套成熟底座。缺口在于平台描述和外设行为仍需工程师主动配置。它不会直接把某块已投产 PCB 的网络表、BOM 和器件资料变成项目模型。原理图连接、模型假设和测试结果之间，也缺少面向硬件评审的可追溯界面。这个产品可把 Renode 藏在后端，重点解决设计文件导入、缺失信息追问和真板测试切换。
- Wokwi：Wokwi 提供微控制器与常见器件仿真，也有逻辑分析、虚拟传感器和自定义芯片能力。其 CLI 能在本机或 CI 运行固件，并按串口输出判定测试结果。 这让 Arduino、ESP32 等项目很快进入可重复测试。现有流程仍以项目配置和虚拟接线图为中心，需要用户准备仿真所需的硬件描述。它没有把制造版原理图、网络表和 BOM 当作主要输入，也不负责逐项解释模型依据。真板到货后的复用路径仍需团队自行搭建。这里的缝隙是面向专业 PCB 项目，把设计资料转换、假设审阅和板前板后对比放进同一条测试链。

## 怎么赚钱（模型推断）

团队订阅，按活跃硬件项目数和并行 CI 用量分档。基础档覆盖常见微控制器与标准外设，高阶档加入私有器件模型、真板测试代理和自托管运行环境。
